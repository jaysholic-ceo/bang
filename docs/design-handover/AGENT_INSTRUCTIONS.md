작성 2026-10-06. 작업 컴퓨터는 Matt 의 Mac, 저장소는 `<로컬 저장소 경로>` 입니다.

**2026-10-09 갱신:** git·배포 규칙(§1 앞의 두 항목)이 바뀌었습니다. 최신 상태와 남은 일은 `docs/HANDOVER.md`, 요약 규칙은 루트 `AGENTS.md` 에 있습니다. 두 문서와 이 문서가 다르면 `AGENTS.md` 를 따릅니다.

## 1. 절대 지킬 것

- 작업은 `ui/ux-refresh-2026-10` 브랜치에서 합니다. (2026-10-09 변경) 라이브 사이트가 아직 개발 서버라 `main` 직접 push 를 Matt 이 허용했습니다(2026-10-07). Matt 이 "적용해줘", "올려줘", "라이브에 적용" 이라고 하면 커밋하고 `git merge --ff-only` 로 `main` 에 합쳐 push 합니다. 그런 말이 없으면 변경은 작업 폴더에 남기고 보고만 합니다. 올리기 전에 `git fetch` 로 `origin/main` 이 앞서 있지 않은지 확인합니다.
- 강제 푸시, 브랜치 삭제, `git reset --hard`, `git clean`, `git add .`/`git add -A` 는 하지 않습니다(추적하지 않는 폴더가 딸려 들어갑니다). 파일을 지정해서 add 합니다.
- 파일을 삭제하지 않습니다. 정리 대상(`README.md` 6번의 사용하지 않는 에셋 목록 등)은 목록만 보고하고, Matt 의 승인을 받은 뒤에만 지웁니다.
- `.env`, `.env.local`, `prisma/` 와 DB 관련 파일은 열어 보거나 수정하지 않습니다. 비밀번호·키 값을 응답이나 문서에 옮겨 적지 않습니다.
- 바꾸는 범위는 화면(프레젠테이션 계층)뿐입니다. API 라우트, DB 스키마, 데이터 수집·저장 로직, 분석 스크립트(gtag, 네이버 WCS)는 건드리지 않습니다.
- 화면의 문구는 병원의 것입니다. 새 문구·새 수치·새 의료 효능 표현을 만들어 넣지 않습니다. 이미 사이트에 있는 문구를 고치거나 새로 넣을 때는 Matt 에게 먼저 묻습니다. 의료광고 관련 판단은 병원 몫이고, 에이전트가 법적 판단을 하지 않습니다.
- "AI 가 만든 느낌"을 피합니다. 그라데이션, 블러, 유리 효과, 글로우, 3D 매끈한 일러스트, 크림·아이보리 배경, 순수 검정, 이모지 장식, 의미 없는 보라·청록 포인트를 넣지 않습니다. 새 장식 요소를 임의로 추가하지 않습니다.
- 직접 그린 SVG, 스톡 사진, 생성한 이미지를 최종 에셋으로 넣지 않습니다. 에셋은 Claude Design 이 만들어 납품한 파일이나 병원이 제공한 사진만 씁니다. 지금 저장소에 있는 `public/images/illust/*.svg` 등은 임시 자리표시이고 교체 대상입니다.

## 3. 이번 브랜치에서 이미 들어간 화면 작업

- 수치 띠: `src/components/home/StatsBand.tsx`(새 파일). `src/app/HomeClient.tsx` 에서 철학 섹션 다음, 본원소식 앞에 연결되어 있습니다. 숫자가 올라가는 모션이고, 모션 줄이기 설정에서는 이동·페이드 없이 숫자만 짧게(1.2초) 올라갑니다. 낭독기에는 최종값만 읽히게 되어 있습니다. 이 구조(aria-hidden 애니메이션 값 + sr-only 최종값)를 유지합니다.
- 개원 햇수는 하드코딩하지 않습니다. `src/lib/clinic.ts` 의 `CLINIC_YEARS`(= 올해 − 개원 연도 2008)를 씁니다. 개원 햇수를 말하는 문구에 "18년"·"20년" 같은 숫자를 직접 쓰지 말고 이 값을 가져다 씁니다. 이미 홈 히어로·연혁 제목·후기 문구, 푸터, `/intro` 본문과 배지·메타 설명, `layout.tsx` 메타 설명이 이 값을 씁니다.
- 일부러 그대로 둔 "20년"이 있습니다. `/intro/doctor-choi` 의 "20년의 임상 경험", `MedicalDetailClient.tsx` 의 "20년의 경험"·"20년 임상 경력"은 개원 햇수가 아니라 의료진 경력 표현입니다. 근거는 병원이 확인할 일이므로 바꾸지 않습니다.
- 수치 띠의 다른 수치(80만 명, 3인)는 사이트 본문에 이미 있던 값입니다. 바꾸거나 새 수치를 넣을 때는 병원 확인이 먼저입니다. 네 번째 칸은 2026-10-16에 "5층"에서 "다수 출연"(KBS·MBC·SBS·MBN 등 주요 방송)으로 바꿨습니다(Matt 결정: 층수는 자랑거리가 아니고, 횟수는 확인된 값이 없어 숫자 없이 표현). "출연" 표현은 병원 확인 대기입니다.

## 4. 작업 순서

1. 납품 파일(SVG·WebP·JPG)이 있는지 확인합니다. 없으면 그 항목은 건너뛰고 "납품 대기"로 보고합니다. 에셋을 직접 만들어 채우지 않습니다.
2. 납품 파일을 `04-delivery-spec.md` 의 위치·이름으로 `public/` 또는 `src/app/` 에 둡니다. 용량 상한(시설 200KB, 아이콘 3KB, 공유 이미지 300KB 등)을 넘으면 넣지 않고 보고합니다.
3. `05-checklist.md` 의 합격 기준을 확인합니다. SVG 는 viewBox 필수, 색은 토큰 `#RRGGBB` 만, 그라데이션·필터·블러·내장 비트맵 금지, 글자는 윤곽선으로 변환되어 있어야 합니다.
4. `README.md` 4번 표의 "코드 위치"에서 이미지 경로만 바꿉니다. 색·구성·문구는 바꾸지 않습니다. 코드 변경이 필요하다고 표에 적힌 항목(시설 자리표시, 히어로 정지 이미지, 질환 아이콘의 이미지 경로 방식)은 작은 단위로 나누어 하고, 각 변경 뒤에 빌드를 확인합니다.
5. 대체 텍스트(alt)는 납품과 함께 온 한국어 문장을 씁니다. 라벨이 옆에 있는 장식용 아이콘의 alt 는 비웁니다.
6. 교체가 끝난 임시 파일은 목록으로 Matt 에게 보고하고, 삭제 승인을 받은 뒤에만 지웁니다.

## 5. 확인 방법

- 빌드: `npm run build` 가 오류 없이 끝나야 합니다. `npm run lint` 도 실행해 새 오류가 없는지 봅니다. 기존에 있던 경고와 새로 생긴 경고를 구분해서 적습니다.
- 테스트: `npm run test`(vitest), `npm run test:e2e`(Playwright, `tests/landing.spec.ts`). 바꾼 화면과 관련 있는 것만 돌려도 됩니다. 실행하지 못한 것은 이유와 함께 적습니다.
- 화면: `reference/captures/` 와 같은 6개 페이지(홈, 병원 소개, 주요 질환, 진료 안내, 본원소식, 커뮤니티)를 데스크톱 1440px, 모바일 390px 로 찍어 비교합니다. `docs/design-handover/tools/capture.py` 를 쓰면 됩니다. 캡처는 저장소 밖(`/tmp/jiin-captures`)에 저장하고, 저장소 안에 `captures-new` 같은 폴더를 만들지 않습니다. 확인이 끝나면 띄운 서버를 종료합니다. 텍스트 잘림, 가로 스크롤, 이미지 비율 깨짐, 글자와 배경 대비를 눈으로 봅니다.
- 모션이 있는 곳(수치 띠)은 모션 줄이기 설정에서도 한 번 확인합니다.
- 확인하지 않은 것을 확인했다고 쓰지 않습니다.
